## Project Overview

**arteris** - A monorepo organized by boaz with a clear folder structure where each folder has a single responsibility:

| Folder | Content | Format |
|--------|---------|--------|
| `0_Assets/` | Reusable resources: `projeto/` (brand, images, fonts), `requisitos/` (tema.md, requisito.mjs, casca.html), `diagramas/` (theme, icons, logos) | free |
| `1_Requisitos/` | The desired product — no backend, frontend or technology | `.md` versioned (+ `pdf/`) |
| `2_Diagramas/` | Development diagrams (backend and frontend) | `.svg` versioned |
| `3_Arquitetura/` | High-level diagrams: cloud, technologies, integrations | `.svg` versioned |
| `4_CI_CD/` | Delivery structures (pipelines, deploy) | free |
| `5_DEV/` | Code: `backend/`, `frontend/`, `qa/backend/`, `qa/frontend/` | free |

## Key Rules

- **Requirements** are `.md` documents, created/modified by the `requisito` skill following the pattern of `0_Assets/requisitos/tema.md` (front matter and top stamp with project, document, version, date/time and status; history in footer; diagrams and screens as versioned `.svg` images). The `requisito-estilo` skill handles formatting, HTML/PDF generated by `0_Assets/requisitos/requisito.mjs` with `casca.html`, migration of old `.html` files and PDF. `./boaz.sh requisitos` lists documents; `./boaz.sh pdf <document>` exports versioned PDF to `1_Requisitos/pdf/`.

- **Diagrams** are created/modified only by the `diagrama-dev` (2_) and `diagrama-arquitetura` (3_) skills.

- **Every diagram** follows the dark theme of `0_Assets/diagramas/tema.svg` and embeds (inline) any assets used from `0_Assets/`.

- **Diagram naming**: `<legenda>_v<NN>_<AAAAMMDD-HHMM>.svg`. Each change generates a new file with the next version, and in the same task, the previous version is deleted (`git rm`) after all references (requirements `.md` and other files) are updated to the new one; history stays in git.

- `./boaz.sh svg <folder> <legend>` returns the next name; `./boaz.sh diagramas` lists the latest version of each; `./boaz.sh antigas` lists old versions already without reference (`--apagar` removes them).

## Boaz CLI Commands

```bash
./boaz.sh init [project-name]        # Initialize monorepo structure
./boaz.sh requisitos                  # List requirement documents
./boaz.sh pdf <documento>             # Export versioned PDF to 1_Requisitos/pdf/
./boaz.sh svg <pasta> <legenda>       # Get next diagram filename
./boaz.sh diagramas                   # List latest version of each diagram
./boaz.sh antigas [--apagar]          # List old unreferenced diagram versions (--apagar removes them)
./boaz.sh icones [categoria]          # Manage icons
./boaz.sh assets                      # Download/sync assets from GitHub
```

## Architecture Decisions

- **Monorepo** managed by custom `boaz.sh` script
- **Requirements-first** approach: all features start as markdown docs in `1_Requisitos/`
- **Diagrams as code**: versioned SVG diagrams in `2_Diagramas/` (dev) and `3_Arquitetura/` (architecture)
- **Frontend**: Vue 3 + TypeScript + Vite (planned)
- **Component structure**: Feature-based organization under `features/` with shared core under `core/`

## Important Files

- `boaz.sh` - Main monorepo management script
- `.boaz` - Project configuration (stores PROJECT_NAME)
- `0_Assets/requisitos/tema.md` - Requirements template
- `0_Assets/requisitos/requisito.mjs` - Requirements HTML/PDF generator
- `0_Assets/diagramas/tema.svg` - Diagram theme
- `0_Assets/diagramas/icones/` - Icon library

## Skills Available

- `requisito` - Create/edit requirement documents
- `requisito-estilo` - Format requirements, generate HTML/PDF
- `diagrama-dev` - Create/edit development diagrams (2_)
- `diagrama-arquitetura` - Create/edit architecture diagrams (3_)
- `init` - Initialize project structure
